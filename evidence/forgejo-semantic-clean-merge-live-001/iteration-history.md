1. Le scénario live a réussi la PR standard, le merge gate de la branche supérieure, le merge preview Forgejo de la branche inférieure, les deux tests de branche et le test protégé rouge. Le gate a renvoyé `verification_failed` / `merge_attempted=false`. Le runner attendait `proof_failed` et s’est arrêté avant de sauvegarder la lecture API post-refus. Aucune fusion de la PR inférieure n’a été tentée par le gate.
2. Le code a été aligné sur le code d’erreur sérialisé par le binaire (`verification_failed`). La première reprise a relu le PR resté ouvert à la base attendue, a corrigé le code et a observé le test protégé vert. Cette assertion ne démontrait pas l’invalidation d’une preuve passante et a été retirée; les anciens tests de candidat périmé du parcours principal couvrent ce comportement.
3. La seconde reprise a validé le binding conservé du head corrigé et son transcript, a produit la preuve passante, obtenu l’approbation, fusionné au moyen du gate, puis exécuté le critère sur le readback de `main`. Elle s’est terminée code 0. L’instance n’a pas été supprimée.
