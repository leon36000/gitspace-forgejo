# CONTINUATION-208 / run 001 — premier POST direct, avant durcissement transport

Ce run de caractérisation a essayé `POST /forge-team-org/team-review-readback.git/git-receive-pack` avec le token à scopes read-only, en plus du `git push`. Le readback JSON rapporte un statut POST `403`, un GET d’annonce à `403`, le push interrompu au code 128 et la branche cible absente avant/après. Le receiver Rust et le CLI de réconciliation relisent ensuite la PR et l’équipe reviewer avec succès. Forgejo v17.0.0 local (`17.0.0+gitea-1.22.0`, Go 1.26.9; binaire SHA-256 `e5ec437cd6357e8d1b4580cb47ab1daa58a32b33971a63db63446a535d33adb7`; commit de build inconnu).

La première implémentation utilisait `urllib` avec une URL fixée à `127.0.0.1`; le serveur a répondu 403, donc aucun redirect n’a été suivi dans cette observation. L’examen du code a toutefois montré qu’un redirect handler implicite rendait la contrainte moins explicite. Le run final 002 remplace ce transport par `http.client.HTTPConnection(127.0.0.1, 3130)`, qui n’a pas de mécanisme de suivi de redirection, et exige séparément le statut HTTP et une ligne d’access log `POST` pour l’URI exacte. Ce run 001 est conservé comme observation exploratoire, pas comme preuve de la propriété de transport final.

La charge est le pkt-line de flush `0000`, sans commande ni packfile; le serveur refuse l’autorisation avant toute mutation. Cela vérifie l’accès au endpoint direct, mais n’envoie pas un push valide hostile. Résultat, tentative, versions et cleanup sont dans les JSON de ce dossier. Les processus terminent code 0 et aucun listener 3130/receiver ne subsiste. Aucun modèle, coût ou service externe.
