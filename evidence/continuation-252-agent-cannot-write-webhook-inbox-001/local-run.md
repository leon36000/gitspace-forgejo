# CONTINUATION-252 — le sandbox de test ne peut pas écrire dans une inbox webhook masquée

Date : 27 octobre 2026. Environnement : Python 3.12.3, Bubblewrap 0.9.0, Cargo/rustc 1.95.0 (détails dans `environment.json`). Worktree `webhook-005-workspace`, HEAD de base `f3e2bb3a9f9b0cb3dbcd1e03f658f0b6a05119a0`. Ce lot ajoute une sonde opt-in au harnais Bubblewrap de `local-test-adapter`; aucun runtime Forgejo/webhook de production n’a été modifié.

## Résultat

Un test processus crée un fichier canari synthétique privé `webhook-inbox.jsonl` dans un sous-répertoire `.runtime` temporaire sous `/tmp`, puis exécute `mission_012_test_agent_adapter.py` dans le même profil isolé que le harnais : Bubblewrap masque `/tmp` par un tmpfs, désactive le réseau et crée un espace PID séparé. La sonde essaie un `open(O_WRONLY|O_APPEND|O_NOFOLLOW)` suivi d’un append fixe. L’ouverture reçoit une erreur de chemin inaccessible; la sortie rapporte `private_runtime_file_writes_denied=["webhook_inbox"]`. Après la pause contrôlée par protocole de reprobe (aucun vérificateur indépendant ne tourne dans ce test), la sonde est répétée et conserve le même résultat. Le fichier canari hôte reste octet pour octet identique.

Un contrôle positif hôte, limité à un autre fichier canari de test, confirme que la même fonction sait ouvrir et append le marqueur fixe quand le fichier est réellement visible. Le contrôle empêche qu’un probe qui échoue toujours soit présenté comme preuve d’isolation. Le test processus conserve aussi les refus des trois probes de routes API, Web et `git-receive-pack` vers le listener loopback du harness, le refus du credential canari et l’absence de connexion acceptée par le listener.

TDD : le nouveau test échouait d’abord car le builder ne connaissait pas l’option d’écriture. Le premier ajout a ensuite échoué car il cherchait le canari hôte depuis le sandbox; la sonde a été corrigée pour valider la forme fixe du chemin côté sandbox et ne vérifier les métadonnées du fichier synthétique que côté hôte avant lancement. Les essais finaux passent : trois tests ciblés 3/3, module `test_mission_012_sandboxed_test_adapter` 11/11. Python `py_compile`, `cargo fmt --all -- --check`, `git diff --check` passent. Le premier helper a ajouté les entrées aux trois index, puis son parseur strict a échoué sur des lignes vides historiques; il n’a supprimé ni remplacé aucune ligne. Le rapport [de vérification des manifestes](manifest-verification.md) conserve cet incident et prouve par un lecteur tolérant la préservation des préfixes et les derniers hashes.

## Portée et réserves

C’est un contrôle de frontière processus local avec un canari synthétique; il ne lance ni Forgejo, ni LLM, ni AgentOS et ne teste pas l’inbox réelle. Il établit que le profil Bubblewrap du harness cache un chemin `/tmp` hôte au test-adapter et refuse l’écriture sur ce chemin; il ne prouve pas une protection cryptographique du journal, une isolation face à un acteur privilégié ou un autre processus hôte du même UID, ni l’exclusion de tous les writers Forgejo. Le code webhook ne persiste toujours pas la signature HMAC originale : `ingest_forgejo_delivery` la vérifie avant append, puis le replay valide le hash-chain local et l’enveloppe. La décision de faire confiance au writer hôte reste explicite; CONT-252 ne prétend pas remplacer cette frontière par une attestation indépendante.

Les travaux précédents restent requis pour le parcours complet, les refus restants, l’autorité atomique de fusion, un runtime LLM/AgentOS autorisé et le benchmark comparatif. Aucun coût fournisseur ni accès nouveau n’a été engagé.
