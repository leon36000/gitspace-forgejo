# WEBHOOK-025 — revue ciblée Forgejo v17

Revue indépendante en lecture seule du code Forgejo officiel au commit `0d791421f85ca13a63b665053d81ea765fbbc571`, associé à la release v17.0.0 annoncée le 15 octobre 2026.

- [`GetTreeBySHA`](https://codeberg.org/forgejo/forgejo/src/commit/0d791421f85ca13a63b665053d81ea765fbbc571/services/repository/files/tree.go#L18) résout un SHA de commit vers ses entrées de racine; le champ de réponse `sha` est ce SHA de commit. Le service retourne `truncated = total_count > per_page`, y compris sur une page finale partielle ([pagination](https://codeberg.org/forgejo/forgejo/src/commit/0d791421f85ca13a63b665053d81ea765fbbc571/services/repository/files/tree.go#L56)).
- `GitTreeResponse` expose `SHA`, `Entries`, `Truncated`, `Page`, `TotalCount`; `Entries` n’a pas `omitempty` ([struct](https://codeberg.org/forgejo/forgejo/src/commit/0d791421f85ca13a63b665053d81ea765fbbc571/modules/structs/repo_tree.go#L16)). Pour une racine vide, le service retourne avant d’allouer la tranche; Go sérialise donc `tree` à `null`. Le lecteur local accepte `null` seulement avec `total_count == 0`, page 1 et `truncated == false`.
- Les entrées v17 comprennent `path`, `mode`, `type`, `size` et `sha`; `size` est un entier signé dans le struct. Le lecteur exige les modes/types Git connus, les identifiants complets, l’unicité des chemins, une pagination cohérente et des plafonds de 100 pages/100 000 entrées. Il compare les entrées de racine triées du commit candidat et du commit de fusion; c’est une vérification de binding du tree, pas une preuve de correction du logiciel.
- Un 4xx de POST ne produit `rejected` que si la lecture indépendante retourne aussi `merged: false`. Si Forgejo montre `merged: true` mais que le commit, le parent ou le manifeste ne permet pas de confirmer le candidat, le résultat reste `inconclusive`.
- La politique de réconciliation autorise uniquement des GET sans corps sur l’issue ou la pull request du dépôt fixé, et refuse les routes imbriquées avant le transport. Le préflight et le gate de merge conservent leur politique API distincte.

Le réviseur n’a pas exécuté ces changements ni vérifié un serveur live; les tests de ce paquet sont décrits dans `webhook-025-local-run.md`. Forgejo v17 local n’était pas lancé et l’image Docker `codeberg.org/forgejo/forgejo:17.0.0` n’était pas présente; aucune image n’a été téléchargée. Les lectures API multiples ne sont pas atomiques et ne bloquent pas un writer Forgejo non coopératif.
