**Date : 22 octobre 2026. Portée : bac à sable local uniquement.** Cette preuve décrit un essai fonctionnel unique sur un petit dépôt Rust synthétique. Elle ne mesure pas un gain général et ne constitue pas un déploiement.

- Le test adversarial `candidate_cannot_forge_libtest_success_with_print_and_process_exit` refuse un candidat qui imprime les marqueurs de libtest puis quitte avec code 0. Les tests du vérificateur lient les snapshots aux trees Git fournis localement et refusent des sources non autorisées, critères altérés et preuves non fraîches. Cela ne protège pas contre un autre processus hôte du même UID qui modifierait cette copie privée en contournant ses permissions; l’hôte reste de confiance.
- Le binaire de vérification exécute les copies de base et candidat dans Bubblewrap avec namespaces user/mount/PID/réseau, sources read-only, nouvelle cible Cargo privée et aucun montage de home ou de credentials. `tests/mission_012_mcp_lifecycle.rs` lance le vrai processus MCP et exerce l’initialisation, la liste d’outils, le rouge, l’écriture, le vert, `shutdown`, le refus d’un appel après arrêt, `notifications/exit` et le reçu final. - Une empreinte atteste l’intégrité de l’objet mesuré, pas la correction du programme. Le processus hôte, le compte admin Forgejo et `verifier-bot` restent de confiance dans ce bac à sable.

## Limites restantes

- AgentOS, Forge Code, RAG, mémoire existante et Ollama n’ont pas été intégrés. Le parcours prouve une interface MCP locale avec Claude Code, pas un adaptateur de production ni l’intégration AgentOS/Ollama.
- L’approbation a été émise par un bot de vérification local; aucune revue humaine indépendante n’a eu lieu. La règle Forgejo ne protège pas d’un administrateur ou du détenteur du token du vérificateur.
- Le binaire local valide un dépôt Git fourni par son appelant, pas l’origine Forgejo ou la relation PR/branche protégée. Le readback opérateur du bac à sable fait la correspondance dans cet essai; un gate déployé devra obtenir ces références d’un adaptateur Forgejo de confiance. Le processus du même UID que l’hôte peut aussi changer les copies épinglées malgré leurs modes read-only.
- Le sandbox réduit l’accès du processus candidat mais ne protège pas contre l’administrateur OS, les failles noyau/outils, les tests incomplets ou un vérificateur compromis. Aucun attestateur matériel ni signature externe n’est utilisé.
- Les refus de statut, falsification de sortie et fraîcheur sont vérifiés en API locale et tests ciblés. Ce parcours unique ne démontre pas à lui seul les webhooks désordonnés, un crash pendant le merge, des conflits sémantiques multi-agents ou la restauration d’une mission LLM interrompue.
- L’instance Forgejo `127.0.0.1:3132`, les identités, l’issue, le dépôt, les tokens et workspaces sont locaux et ignorés sous `.runtime/`. La PR locale ne peut pas être attachée comme artifact Codex, car le connecteur refuse les URL `127.0.0.1`.

Les preuves d’exécution privées et le transcript Claude restent sous `.runtime/mission-012-agent-run-001/`; ils ne contiennent aucun token dans ce rapport. Les rapports structurés sont [le verdict pré-fusion](mission-012-independent-proof-premerge.json), [le verdict post-fusion](mission-012-independent-proof-postmerge.json), [le readback Forgejo et Git](mission-012-forgejo-postmerge.json), [le refus HTTP 403 du statut agent](mission-012-agent-status-refusal.json), [le résumé MCP expurgé](mission-012-mcp-lifecycle-summary.json), [le résumé d’usage du modèle](mission-012-model-run-summary.json) et [la sortie Cargo complète](mission-012-full-cargo-test.log).
