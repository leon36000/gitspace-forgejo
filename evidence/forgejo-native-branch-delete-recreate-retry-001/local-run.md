# FORGEJO-NATIVE-BRANCH-DELETE-RECREATE-RETRY-001

Date : 26 octobre 2026. Ce lot étend le parcours local précédent : Forgejo v17 crée une branche, émet deux événements natifs `create` et `delete` (après avance), puis le receiver Rust les accepte. Au premier readback, la branche est absente et le CLI répond `inconclusive/resource_not_found` pour les deux livraisons, sans état canonique. Le runner désactive ensuite le hook et confirme sa désactivation avant de recréer la branche, afin qu’aucune nouvelle tâche webhook ne soit produite. Il lit le SHA courant par le compte Forgejo de lecture seule, puis relance le CLI avec les mêmes deux IDs dans le même ordre. Les deux résultats sont `current_state_read`, lient la même branche au SHA courant, et le batch déclare un seul read upstream.

Le reçu compare l’inbox avant et après les deux tentatives octet pour octet; les fichiers d’évidence conservent l’ordre et l’identité des IDs. La lecture SQLite locale confirme exactement deux tâches webhook (create/delete, HTTP 202), identiques avant et après la recréation. Le reçu vérifié est sous [live-run-002](live-run-002/result.json); le validateur indépendant revérifie les deux manifestes d’exécution et les assertions de transition : [verify_retry_receipt.py](verify_retry_receipt.py). La trace de la première tentative rouge du harnais et de son correctif est conservée dans [harness-red-first.md](harness-red-first.md); elle a échoué au sérialiseur après la transition et le nettoyage a arrêté les services.
