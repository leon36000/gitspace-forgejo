# WEBHOOK-BATCH-CACHE-001 — cache JSON borné pour la réconciliation par lot

Date : 24 octobre 2026. Base Git observée avant ce lot : `f3e2bb3a9f9b0cb3dbcd1e03f658f0b6a05119a0`. Le worktree était déjà très modifié; aucun commit ni nettoyage n’a été effectué.

## Changement

`reconcile_inbox_events` comptabilise maintenant les octets JSON non compressés produits par la sérialisation des réponses qu’il garde dans son cache. Le cumul est plafonné à 8 Mio, distinct du plafond de 1 Mio par corps HTTP annoncé par le client local. La réponse qui dépasse le cumul a déjà été reçue puis sérialisée : elle est rejetée et n’est pas conservée. Les ressources uniques suivantes retournent une erreur `batch_cache_budget_exceeded` sans GET additionnel; les ressources déjà mises en cache restent disponibles, y compris un rejeu avec un nouvel ID de livraison. Le résultat du lot reste `inconclusive`, la limite est non réessayable et l’action demande de fractionner le lot.

La mesure borne les octets JSON comptabilisés, pas la taille exacte du tas Rust, le pic transitoire de sérialisation ni le trafic réseau. Le contrat de capacité expose `maximum_cached_json_bytes=8388608` et `cache_budget_measurement=combined_uncompressed_serialized_json`; la limite HTTP individuelle reste `max_response_bytes=1048576`. Voir [l’implémentation](../src/webhook/reconcile.rs#L8), [le mapping d’erreur et la découverte des capacités](../src/bin/forgejo-reconcile-local.rs#L1099) et le [snapshot de capacités du binaire release](webhook-batch-cache-001-capabilities.json).
